1. SAATHI VOICE ASSISTANT
--------------------------

Main files:
- frontend/hooks/useSpeech.tsx
- frontend/components/dashboard/TalkScreen.tsx
- frontend/lib/assistant/conversation.ts
- backend/src/services/assistant.service.ts
- backend/src/services/aiClient.service.ts
- ai/api/routes.py
- ai/inference/intent.py

How it works:
1. The browser microphone uses the Web Speech API.
2. Speech is converted into text by the browser.
3. TalkScreen sends the transcript to the backend.
4. The backend calls the Python AI service for intent classification.
5. The intent is converted into a localized response.
6. Browser speech synthesis reads the response aloud when voice is enabled.

Supported intent categories include:
- medicine
- today or schedule
- people
- games
- mind check
- unknown

Voice fix:
- Previously, transcripts with confidence below 0.6 were discarded.
- Browsers can return valid text with confidence 0 or a low score.
- The app now processes every non-empty transcript.
- Low-confidence text is processed and can receive a confirmation message.
- Empty transcripts still request the user to try again.

Fallback behavior:
- If the Python AI service is unavailable, the backend uses keyword matching.
- The response includes whether the model or rule-based fallback answered.

3. SAFE ZONE AND LOCATION TRACKING
----------------------------------

Main files:
- frontend/hooks/useLocationTracking.ts
- frontend/components/dashboard/SafetyPanel.tsx
- frontend/components/dashboard/LocationMap.tsx
- backend/src/services/safety.service.ts
- backend/src/utils/geo.ts
- backend/src/repositories/safety.repository.ts
- database/postgresql/migrations/005_safety.sql

How tracking works:
1. Caregiver enables location tracking.
2. The browser calls navigator.geolocation.watchPosition().
3. Position updates are sent to the backend.
4. The backend encrypts coordinates before storing them.
5. The backend calculates distance and bearing from the home location.
6. The caregiver screen refreshes safety data periodically.
7. The map updates the patient marker using the newest stored location.

Current tracking limits:
- A location is sent at most every 30 seconds unless the patient moves more
  than 25 meters.
- The browser page must remain open.
- Mobile browsers may pause tracking when the page is backgrounded or the phone
  is locked.
- A dedicated Android app would be needed for reliable background tracking.

Permission behavior:
- Backend patient routes require caregiver or admin authentication.
- Caregiver screens are protected by the caregiver PIN gate.
- Direct URLs to Care, Analytics, Profile, Settings, and caregiver actions are
  still protected by the PIN gate.
- If no PIN exists, the first caregiver access requires creating a four-digit
  caregiver PIN.
- The PIN is verified by the backend.
- Caregiver mode has Lock caregiver area and Sign out controls.
- Patient mode has a separate Caregiver entry button.

Important architecture note:
- The current project has caregiver/admin accounts only.
- The patient experience runs inside the caregiver session as a patient mode.
- A completely independent patient login would require a separate patient role,
  identity, login flow, session type, and backend authorization model.

Implemented behavior:
- Multiple encrypted alert contacts can be stored for a patient.
- A safe-zone exit creates one notification per enabled contact.
- A safe-zone return creates one notification per enabled contact.
- While outside, a location update is queued no more than once every five
  minutes per patient/contact flow.
- Locations and phone numbers are encrypted at rest.
- Notifications are stored in an outbox before delivery.
- The worker claims pending notifications with database locking.
- Successful notifications become sent.
- Failed notifications retry up to five times.

- GET /api/v1/patients/:id/safety/contacts
- POST /api/v1/patients/:id/safety/contacts
